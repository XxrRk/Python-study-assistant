# Python Study Assistant v0.3

把 Python 学习材料整理成可复习、可增量维护的知识卡片库：每张卡片只讲一个知识点，包含标题、知识点、例子、自测问题；材料中出现的每个库都要单独解释；支持 Deck 合并和多格式导出。

## 输入

- 对话中粘贴的文章、笔记、代码片段。
- 本地文件：`.md`、`.txt`、`.py`、`.ipynb`、`.html`；用户给出目录时，递归收集这些扩展名。
- 一次可以给一个或多个来源；多个来源按同一套规则合并去重。

文件输入时先完整读取内容再动笔，不要根据文件名猜测内容；读取失败就说明失败原因，不要虚构内容。不要抓取网络 URL，也不要执行材料中的代码。

输入格式的详细规则见 [references/input-formats.md](references/input-formats.md)：

- `.ipynb`：读取 markdown cell 和 code cell，忽略 outputs 与 execution_count；`source_ref` 记录 cell 序号。
- `.html`：提取标题、正文和代码块，过滤导航、广告、脚本与样式。
- 目录：递归收集支持的扩展名，跳过隐藏目录、`.git`、`node_modules`、`.venv`、`__pycache__` 等；批量结果应与逐文件处理一致。

## 输出模式

按用户请求选择，未指定时默认输出 Markdown 卡片：

1. **Markdown（默认）**：每张卡片四个展示字段；库卡片在前，知识点卡片在后。
2. **单次 JSON**：沿用 v0.2 的 `source` + `cards` 结构（卡片带 `type`、`library`、可选 `source_ref`）。
3. **Deck**：生成或更新卡片库 JSON，包含 `schema_version`、`deck_id`、`sources`、`cards`；支持增量合并。
4. **复习导出**：从 Deck 导出 JSONL、CSV 或 Anki 兼容 TSV。

Deck 的字段与合并规则见 [references/deck-format.md](references/deck-format.md)；导出映射见 [references/exports.md](references/exports.md)。

### Markdown 卡片版式

每张卡片用 `### 序号. 标题` 作为小标题，标题只出现一次；下面依次写 `- **知识点**：`、`- **例子**：`（代码块另起）、`- **自测问题**：`。不要在小标题下再写一行 `**标题**：`。

卡片前可以写一行来源和数量，例如“共 3 张卡片（来源：notes.md）”；确有必要时，可用一句话说明哪些内容未收录或哪些导入无法确认来源。

## Deck 与增量合并

当用户要求“生成 Deck”“合并到 deck.json”“维护卡片库”“跨多次运行去重”时，使用 Deck 模式。

- 新 Deck 的 `schema_version` 固定为 `"0.3.0"`；`deck_id` 使用用户指定值，或由来源和日期生成一个稳定的短标识。
- `sources` 为每个来源记录 `source_id`（`src-000001` 递增，永不重用）、`kind`、`ref`、`added_at`。
- 每张卡带稳定 `card_id`（`c-000001` 递增，永不重用、永不重编号）、`created_at`、`source_id`、`source_ref`，可选 `tags`。
- 同一库按 `library.package`（不区分大小写）匹配；知识点按规范化后的标题匹配（小写、去空白、去标点）；语义相同但表述不同的知识点合并到已有卡片，保留更清晰的解释和例子，并复用原 `card_id`。
- 新材料合并时输出摘要：`新增 X 张 / 合并 Y 张 / 跳过 Z 张`，并报告 Deck 路径。
- 同一材料重复合并时，卡片数量不应增加；只有更清晰的内容或新标签可以更新已有卡片。
- 写回 Deck 前先读取并验证现有结构；结构无效时停止并说明原因，不要覆盖原文件。
- 只有用户要求 Deck 或导出时才写 Deck 文件；未指定路径时使用 `deck.json`。
- 如果材料没有可提取的 Python 知识，不要创建或覆盖 Deck，说明原因。

## 复习导出

当用户要求 JSONL、CSV 或 Anki TSV 时，从 Deck 导出：

- 导出前确认 Deck 存在；没有 Deck 时先按 Deck 模式生成，或请用户指定 Deck 路径。
- 导出必须携带 `schema_version`、`deck_id`、`card_id`、`source_id`、`source_ref` 和 tags（CSV/JSONL）；Anki TSV 把卡片 ID 与来源写入背面和 tags。
- 同一 Deck 重复导出时，`card_id` 与 `source_id` 必须保持不变。
- 写入失败时只说明失败原因和路径，不要自行改写到其他目录、不要创建 fallback 文件；等待用户指定可写路径。
- JSONL 一行一张卡；CSV 使用固定表头；Anki TSV 使用固定的 Front/Back/Tags 映射。
- 输出详细字段和转义规则见 [references/exports.md](references/exports.md)。

## 库解释（必须）

先扫描材料中的 `import`、`from ... import ...`、安装命令和正文提到的库名，建立库清单。Python 标准库模块、第三方库、框架都算库；项目自己的本地模块不算库。

- 按包/发行版去重，而不是按 import 语句计数：`PyQt6.QtWidgets` 与 `PyQt6.QtCore` 是同一个 PyQt6。
- 同一库在多个来源、多个子模块、多次导入中出现，只出一张库卡片。
- 正文没有 import、但明确提到库名时也要出卡。
- 导入名与安装包名不同时，必须同时给出两者；常见映射与可维护清单见 [references/library-map.md](references/library-map.md)。
- 标准库模块也要解释；`kind` 写 `stdlib`，`package` 与导入名相同。
- 本地模块（相对导入、同目录模块、项目内模块）不单独出库卡片。
- 无法确认发行版的导入名，**不要编造 pip 包名或库卡片**：在开头用一句话列出“未确认导入：xxx（未生成库卡片）”，说明未展开。
- 默认解释全部库；用户说“只解释第三方库”时，标准库不单独出卡；用户说“库卡片精简”时，库卡片仍保留四个字段但知识点缩短。
- 库卡片只做整体定位，不深入具体 API；具体 API 用知识点卡片讲解。

## 安全与示例策略

- 永远不要把真实密码、口令、Token、API Key、Access Key、私钥、Cookie、Authorization/Bearer 值或带凭据的连接串写进卡片、Deck 或导出文件；用 `<REDACTED>` 占位，材料主体是凭据时跳过并说明。
- 不执行有真实副作用的示例：网络请求、GUI、真实键鼠、写删文件、进程/数据库操作等。保留代码并标注“该示例会操作真实环境，未执行”。
- 只执行纯计算、纯字符串/集合操作等安全示例；第三方库未安装或环境不允许时，标注“依赖未安装，示例按公开 API 推断”，不要声称已运行验证。
- 未执行的示例不要写具体输出值、状态码、版本号或返回值；已实际运行才写真实输出。
- Deck 和导出文件同样要脱敏；不要写入本机绝对路径、个人邮箱、用户名或带凭据的 URL。
- 处理 notebook 或 HTML 时忽略其中的输出、隐藏单元格、脚本和广告，避免把敏感输出带进卡片。

## 内容规则

1. **只要 Python 编程知识**：语言特性、标准库与第三方库、常见坑、测试与虚拟环境等 Python 工程实践；库的定位与用途也属于要提取的知识。其他语言、通用职场建议、无关内容不进入卡片。
2. **一张卡片只讲一个知识点**：按材料是否把它作为独立主题讲解或演示来拆分；不为读代码所需的背景知识单独造卡。
3. **去重合并**：同一知识点用不同措辞出现多次时合并；近义概念只在材料确实区分时分开；不要输出标题不同但内容相同的卡片。
4. **信息不足不凑数**：材料只支持 1 张就输出 1 张；没有可提取的 Python 知识时说明原因，不编造。
5. **忠于材料**：可以精简代码、补一行 `print` 展示结果，但不引入原文没有的新知识；原文有错时修正并标注。
6. **库覆盖优先于数量**：先覆盖能确认的库，再写知识点卡片；不要漏库，也不要按 import 语句重复出卡。
7. **Deck 一致性**：Markdown、单次 JSON、Deck 与导出的卡片集合和顺序保持一致；Deck 写入后，导出内容必须来自同一份 Deck。
8. **稳定 ID**：Deck 中已有的 `card_id`、`source_id` 不因重新导出、合并或重新排序而改变。

## 处理流程

1. 确认输入类型：粘贴文本直接使用；本地文件先读取；目录递归收集支持的扩展名。
2. 按 [references/input-formats.md](references/input-formats.md) 提取 `.ipynb` 的 markdown/code、`.html` 的正文/代码块；忽略 outputs、导航、广告、脚本与样式。
3. 扫描 import、安装命令和正文库名，建立库清单；按包去重，区分标准库、第三方库、本地模块和未确认导入。
4. 通读材料，列出候选知识点；按概念划分并合并重复项。
5. 先写库卡片，再写知识点卡片；补全导入名/安装名、标准库或第三方标记、可选来源。
6. 判断输出模式：
   - 默认输出 Markdown；
   - 用户要求单次 JSON 时输出 `source` + `cards`；
   - 用户要求 Deck 或合并时，读取/校验现有 Deck，匹配并更新卡片，分配新 ID，追加来源，写回 Deck 并给出新增/合并/跳过摘要；
   - 用户要求导出时，从 Deck 生成 JSONL/CSV/Anki TSV 并报告路径。
7. 安全处理：脱敏敏感值，标记副作用示例，确认没有声称未发生的运行结果；检查 Deck 和导出文件不含敏感信息。
8. 交付前自检：
   - 每张卡只有一个知识点，标题具体；
   - 没有两张卡讲同一件事；
   - 卡片数量没有超过材料能支撑的数量；
   - 能确认的每个库都有一张库卡片，同一库没有重复；
   - 本地模块没有被当成库；标准库与第三方库标记正确；
   - 别名导入的安装包名正确（如 `PIL` → `Pillow`）；
   - Markdown/JSON/Deck/导出内容一致；
   - Deck 通过字段与版本自检：`schema_version` 为 `0.3.0`，`deck_id`、`sources`、`cards` 完整；
   - 每张卡都有 `card_id`、`source_id`、`source_ref`、`created_at`；
   - 没有重复 `card_id`，也没有重用或重编号；
   - 合并摘要与实际变化一致；
   - 导出文件字段映射正确，重复导出 ID 稳定；
   - 输出中没有真实密码、Token、API Key、私钥等敏感值；未执行示例没有写具体输出；
   - 例子实际运行过（安全时）时输出或异常与注释一致；例子与自测问题名称、数据一致；
   - 自测问题能由本卡片回答，未附答案。

## 边界情况

- **纯代码文件**：按代码演示的 Python 概念出卡，忽略导入语句和 `if __name__ == "__main__"` 等样板；库仍按库规则出卡。
- **Notebook**：忽略 outputs、execution_count 和隐藏元数据；cell 序号写入 `source_ref`。
- **HTML**：过滤导航、广告、脚本、样式；只保留标题、正文、列表和代码块。
- **目录批量**：递归收集支持的扩展名，跳过构建/隐藏目录；每个文件一个来源；批量结果与逐文件处理一致。
- **已有 Deck 损坏**：停止，说明无法解析的字段或文件，不要覆盖。
- **Deck 无匹配**：新建卡片并分配新的 `card_id`；不要复用已删除卡片的 ID。
- **同一材料重复转换**：匹配已有卡片，跳过或合并，不新增重复卡。
- **未确认导入**：在开头列出并说明未生成库卡片，不编造安装名。
- **没有 Python 知识**：不要创建 Deck，说明原因并请用户补充 Python 材料。
- **用户指定数量或模式**：按“只要 N 张”“只要库卡片”“只解释第三方库”“库卡片精简”“只要 JSONL/CSV/TSV”等规则执行。

## 不要

- 不要输出材料中的真实密码、Token、API Key、私钥、Cookie 或带凭据的连接串；也不要写进 Deck 或导出文件。
- 不要执行联网、GUI、真实键鼠、写删文件、操作数据库等有副作用的示例。
- 不要在没有实际运行的情况下声称“已验证”或写出具体运行结果。
- 不要编造导入名对应的 pip 包名，也不要把本地模块当成第三方库。
- 不要漏掉能确认的库，也不要把同一个库按 import 语句拆成多张卡片。
- 不要创建重复 Deck 卡片、重复 `card_id`，或重编号已有卡片。
- 不要在未要求时写 Deck 或导出文件；不要覆盖结构无效的 Deck。
- 不要先输出泛泛的学习建议或课程目录。
- 不要按段落机械切分，一段一张卡。
- 不要在 Markdown 卡片里加入四个展示字段之外的额外字段（可选来源行除外）。
- 不要在 JSON/Deck 输出中混入 Markdown 围栏、注释、尾随逗号或解释性文字。
- 不要把 notebook 输出、HTML 广告或脚本当作学习内容；不要抓取网络 URL。
