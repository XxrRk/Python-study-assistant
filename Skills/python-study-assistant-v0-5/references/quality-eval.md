# 质量评估与回归（v0.5.0）

本文件定义卡片质量评分、回归不变量和前向测试方法。目标是让 v0.5 的卡片与 Deck 操作可验证，而不是只看格式是否正确；项目仓库的 `tests/quality/cases.json` 是这套规则的机读基线。

## 评分表

每项 0–2 分，满分 12 分；发布前建议总分 ≥ 9，且不得有 0 分项。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 库覆盖 | 漏掉可确认的库 | 覆盖大部分，仍有漏 | 每个可确认库都有卡片，本地模块/未确认导入处理正确 |
| 一卡一知识点 | 多概念混杂 | 有少量混杂 | 每张卡只讲一个知识点 |
| 去重 | 明显重复卡 | 少量重复/近重复 | 重复表述合并，近义概念按材料区分 |
| 例子质量 | 无例子或不可运行 | 有例子但不完整/未标注 | 安全示例可运行，副作用示例标注未执行 |
| 自测问题 | 缺失/与卡片无关 | 过于宽泛 | 能由本卡片回答，不附答案 |
| 安全与来源 | 含敏感值/无来源 | 来源不完整 | 无敏感值，来源可追溯，Deck ID 稳定 |

## 回归不变量

对固定 fixture 至少检查：

1. 库覆盖：别名映射正确，同一库不重复，本地模块不算库。
2. 卡片数量：不超过材料支撑范围，不凑数；信息不足时允许少于预期。
3. 去重：同一知识点只保留一张卡；合并后卡片数量不增加。
4. Notebook：忽略 outputs/execution_count；`source_ref` 含 cell 序号。
5. HTML：不出现导航、广告、脚本、页脚的原文内容。
6. Deck：Schema 通过；`card_id`/`source_id` 唯一；ID 不重编号。
7. diff：dry-run 不写文件；摘要与投影变化一致。
8. 跨 Deck：重复卡 0；目标 ID 不变；来源 ID 正确重映射。
9. 迁移：v0.3 Deck 可读，迁移后 ID/内容不变。
10. 筛选导出：筛选条件生效，字段映射正确，重复导出 ID 稳定。
11. 安全：敏感值不出现在卡片、Deck、导出中。
12. 归档：默认不导出；`include_archived` 才包含。

## 前向测试方法

1. 选一组 fixture 和真实用户请求（转换、合并、筛选、迁移、导出）。
2. 让独立 Agent 仅读取 v0.5 Skill，执行请求；不提示答案。
3. 按评分表和回归不变量检查输出、Deck、导出文件。
4. 记录问题：漏库、重复、格式、ID、安全、diff 不一致。
5. 修复 Skill/参考文档后重跑；保留失败用例作为回归材料。

CI 只做静态检查，不调用真实 LLM，也不替代前向测试。

## 发布门槛

- 每个 P0 功能至少有 1 份 fixture 和对应不变量；
- 质量评分无 0 分项，总分 ≥ 9；
- 结构/Schema/版本/安全 CI 全绿；
- 前向测试覆盖转换、Deck diff、跨 Deck、迁移、筛选导出与安全。
