# 长材料分块与覆盖报告（v0.6.0）

当材料超过一次舒适阅读的长度（经验值：数十段代码/多个大章节），按本节处理，避免只读开头、重复出卡或漏掉后半部分。

## 分块策略

1. 先扫描整体结构：标题、章节、代码块密度。
2. 按一级/二级标题切成小节；没有标题时按连续段落 + 代码块自然边界切分。
3. 每块独立读取，记录：
   - 块 ID / 标题；
   - 是否包含 Python 知识；
   - 候选库与知识点；
   - 跳过原因（无 Python、纯配置、重复等）。
4. 合并跨块重复知识点；库卡片全局按包去重。
5. 最后生成覆盖报告。

## 覆盖报告格式

```text
Coverage
source: book.md
sections: 8/8 read
covered: 1 基础语法; 2 路径操作; 4 虚拟环境
skipped: 3 安装截图（无 Python 知识）; 5 广告（噪声）
unconfirmed imports: internal_sdk
cards: 12
```

规则：

- `sections` 必须反映实际读取的章节数；
- 跳过的章节要写原因，不能只写“未覆盖”；
- 不能为了覆盖率把无 Python 知识的章节硬做成卡片；
- 覆盖报告可以放在 Markdown 卡片前，或作为独立说明；不要写入 Deck 卡片。

## 分块去重

- 同一知识点在多个块出现时，保留最清晰版本，合并来源；
- 示例重复但角度不同，可拆成不同知识点；
- 不要因为分块而给同一库生成多张卡片；
- 分块处理完成后，再进行一次全局去重。

## 失败与限制

- 某块无法读取时，在覆盖报告中标记读取失败，不要静默跳过；
- 长材料需要多次读取时，保持章节顺序和来源引用；
- 不要自动抓取网络内容，也不要把远程 URL 当作已读取材料。
