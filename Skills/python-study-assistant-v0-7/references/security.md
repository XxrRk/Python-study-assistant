# 安全预扫描与脱敏（v0.7.0）

在处理材料前做安全预扫描，在写回 Deck 或导出前再复查一次。目标是不把真实凭据、个人信息或本机路径带进公开产物。

## 预扫描范围

### 凭据

- 密码、口令、PIN、数据库密码；
- Token、API Key、Access Key、Secret Key、Client Secret；
- GitHub/GitLab/云服务 Token；
- 私钥、证书、keystore；
- Cookie、Session ID、Authorization / Bearer 值；
- 带用户名/密码的 URI，如 `postgresql://user:pass@host/db`。

### 个人信息

- 邮箱地址；
- 手机号、身份证号、护照号；
- 真实 IP 地址；
- 本机绝对路径、用户名目录；
- 真实姓名、住址等材料中出现的个人数据。

## 处理策略

1. **先扫描再提取**：读取材料后先查敏感模式，再开始拆分知识点。
2. **凭据主体跳过**：材料主要是 `.env`、密钥文件、证书或凭据列表时，跳过并说明，不生成卡片。
3. **局部脱敏**：材料中夹带敏感值时，用 `<REDACTED>` 替代，不把原值写入卡片、Deck 或导出。
4. **来源排除**：不处理 `.env`、`.pem`、`.key`、`.p12`、`.pfx`、`.crt`、`.cer`、`.kdbx` 等密钥/证书文件。
5. **路径处理**：不写本机绝对路径；文件来源只写相对路径或文件名。
6. **写回前复查**：Deck、JSONL、CSV、TSV 生成后再次检查敏感值；发现泄漏时停止写回。
7. **不执行副作用示例**：不运行联网、GUI、真实键鼠、写删文件、数据库操作等代码。

## 测试夹具策略

- 所有测试敏感值必须是明显的占位符，如 `EXAMPLE_API_KEY_VALUE`、`EXAMPLE_GITHUB_TOKEN_VALUE`、`example.invalid` 域名。
- 不使用真实 Token 前缀（`ghp_`、`sk-` 等）、可解析私钥块、真实邮箱/手机号/身份证号。
- 不写入本机绝对路径、个人邮箱或真实 IP。
- CI 扫描 `tests/fixtures/`，发现禁止模式即失败。

## 输出检查

交付前确认：

- 卡片、Deck、导出内容中没有真实密码/Token/私钥/凭据连接串；
- 没有真实个人信息或本机路径；
- 未执行示例已标注，没有具体运行输出；
- 测试夹具符合占位符策略；
- 写回失败时没有生成 fallback 文件。

## 误报处理

- 明显的示例值（如 `example.invalid`、`EXAMPLE_*`）不当作真实凭据，但也不要改写成看起来可用的真实值。
- 无法确认是否敏感时，优先脱敏或跳过，并说明原因。
